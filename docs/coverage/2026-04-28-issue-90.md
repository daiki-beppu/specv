## 5. Playwright trace 観察メモ

`node_modules/.bin/playwright test --trace on` 実行で 25/25 pass / 5.4s（5 worker）。各テスト配下に `trace.zip` が 25 件生成（`test-results/<test>/trace.zip`）。観察ポイント:

- 全テストとも単一スレッド `chromium` プロジェクトで完結。複数ブラウザマトリクス未設定。
- `responsive.test.ts` の mobile / desktop 切り替えは `test.use({ viewport })` で行っており、trace 内でビューポート変化が単一テストで複数発火する箇所はない（`describe` 単位でクリーンに分離）。
- `scroll-containment.test.ts` の trace では `getByText("README.md").click()` 後にプレビューを `wheel` イベントで操作しており、スクロール伝搬抑止の判定が `documentElement.scrollTop` 比較に拠っている。Mermaid / KaTeX 等の遅延ロードによるレイアウトシフトは観察されない範囲。
- trace ファイル 1 件あたり 30 KB〜120 KB 程度。`test-results/` は既に `.gitignore` 管理済みで、リポジトリには取り込まれない。
- **CLI 既知問題**: `nlx playwright test` は「2 つの異なる `@playwright/test` バージョン（dlx キャッシュとローカル devDeps）」検知で起動失敗。`node_modules/.bin/playwright` 直接実行で回避。`package.json` の `test:e2e` は `playwright test` 直叩きのため通常の `nr test:e2e` は問題なく動く（=今回は `--trace on` を引数で渡したいだけのために回避策が必要だった）。
